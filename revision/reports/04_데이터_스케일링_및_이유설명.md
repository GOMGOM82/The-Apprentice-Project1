# 4. 데이터 스케일링 및 이유 설명

## 1. 스케일링의 필요성과 데이터 특성

머신러닝 파이프라인에서 입력 데이터의 각 변수는 저마다 다른 단위와 범위를 가집니다. 본 연구에서 사용하는 14개 사전 변수 역시 측정 척도의 차이가 큽니다.

예를 들어 성별은 0 또는 1의 이진값이고, 여행 성향 설문은 1점에서 7점, 소득 구간은 1에서 12, 여행 일수는 1일에서 8일인 반면, 출발 전 사전 예약금(`ADV_CONSUME_KRW`)은 0원에서 최대 88만 원까지 수치 단위가 수십만 배 이상 큽니다.

이러한 단위 차이가 모델 학습에 어떤 영향을 미치는지 살펴보고, 대표적인 세 가지 기본 스케일러(StandardScaler, MinMaxScaler, RobustScaler)와 이상치 완화 변환들을 비교하여 최적의 전처리를 선정했습니다.

---

## 2. 모델 계열별 스케일링 영향 비교: 거리 기반 vs 트리 기반

스케일링의 필요성을 확인하기 위해 거리 기반 모델인 K-최근접 이웃(KNN, $k=5$)과 트리 기반 모델인 LightGBM에 스케일링을 각각 적용하여 검증 세트(576건)에서의 성능을 측정했습니다.

| 모델 종류 | 스케일링 적용 여부 | 검증 RMSE | 검증 $R^2$ | 관찰된 특징 |
| :--- | :--- | :---: | :---: | :--- |
| **거리 기반 모델** (KNN, $k=5$) | 스케일링 미적용 (Raw) | 353,514원 | **0.0226** | **거리 왜곡 발생**: 88만 원에 달하는 사전 예약금 하나의 거리가 지배하여 성향(1~7점)과 인구통계 변수가 무시됨 |
| | **StandardScaler 적용** | **308,178원** | **0.2572** | **정상 복원**: 변수들의 분산이 동일하게 맞춰지며 오차가 약 4.5만 원 줄어들고 설명력 회복 |
| **트리 기반 모델** (LightGBM) | 스케일링 미적용 (Raw) | 289,371원 | 0.3451 | 단조 변환 불변성으로 스케일링 없이도 정상 작동 |
| | **StandardScaler 적용** | **289,168원** | **0.3460** | 히스토그램 빈 양자화 안정성으로 오차 203원 미세 개선 |

### 트리 모델에서 스케일링의 의미
이론적으로 결정 트리는 변수의 절대적인 수치 크기가 아니라 대소 순서를 보고 분기점(Threshold)을 찾습니다. 따라서 순서가 바뀌지 않는 단조 변환(MinMaxScaler, RobustScaler 등)을 적용하더라도 트리의 분할 결과는 수학적으로 동일합니다.

실제로 LightGBM에서 원본(Raw), MinMaxScaler, RobustScaler, 분위수 변환 등은 검증 오차가 289,370.7원으로 완전히 같게 측정되었습니다.

다만 StandardScaler를 적용했을 때 검증 RMSE가 289,370.7원에서 289,168.1원으로 약 203원(0.07%) 미세하게 감소했습니다. 이는 트리의 분기 성질 때문이라기보다는, LightGBM이 연속형 변수를 256개의 정수 구간(Histogram Bin)으로 나눌 때 부동소수점 양자화 경계가 미세하게 조정되면서 나타난 수치적인 차이입니다.

반면 거리 기반 모델인 KNN에서는 스케일링을 하지 않았을 때 $R^2$가 0.0226으로 모델이 완전히 붕괴되었지만, StandardScaler를 적용하자 0.2572로 11배 이상 회복되었습니다. 이는 유클리디안 거리를 계산하는 모델에서는 스케일링이 절대적으로 필요함을 보여주는 대조적인 결과입니다.

## 3. 데이터 누수(Data Leakage)를 방지한 방법

스케일링 과정에서 흔히 저지르기 쉬운 실수는 전체 데이터(훈련+검증+테스트)의 평균이나 최댓값으로 스케일러를 학습시키는 것입니다. 이렇게 하면 아직 알지 못해야 할 검증 세트나 테스트 세트의 정보가 훈련 과정에 스며드는 데이터 누수(Data Leakage)가 발생합니다.

본 과제에서는 누수를 철저히 차단하기 위해 다음과 같이 파이프라인을 구성했습니다:

```python
# 1. 훈련 데이터(1,728건)로만 스케일러의 평균과 표준편차를 계산(fit)
scaler = StandardScaler()
scaler.fit(X_train)

# 2. 훈련 세트, 검증 세트, 테스트 세트는 계산된 모수를 바탕으로 변환(transform)만 수행
X_train_scaled = scaler.transform(X_train)
X_val_scaled   = scaler.transform(X_val)    # 검증 세트 정보는 계산에 전혀 쓰이지 않음
X_test_scaled  = scaler.transform(X_test)   # 테스트 세트 정보는 계산에 전혀 쓰이지 않음
```

이를 통해 검증 세트와 테스트 세트의 통계량이 훈련 단계에 1비트도 들어가지 않도록 분리했습니다.

## 4. 스케일러 전수 비교 결과 및 최종 선택 이유

검증 데이터(576건)에서 측정한 7종 스케일러의 성능 비교표는 다음과 같습니다.

| 스케일러 | 전처리 유형 | LightGBM 검증 RMSE | LightGBM 검증 MAE | LightGBM 검증 $R^2$ |
| :--- | :--- | :---: | :---: | :---: |
| 원본 (Raw) | 전처리 미적용 | 289,371원 | 138,503원 | 0.3451 |
| **StandardScaler (표준화)** | **필수 표준화 (최종 선택)** | **289,168원** | **138,466원** | **0.3460** |
| MinMaxScaler (정규화) | 필수 0~1 선형 압축 | 289,371원 | 138,503원 | 0.3451 |
| RobustScaler (강건 표준화) | 필수 중앙값/사분위수 기반 | 289,371원 | 138,503원 | 0.3451 |
| QuantileTransformer | 정규분포 분위수 변환 | 289,371원 | 138,503원 | 0.3451 |
| Yeo-Johnson Power | 분산 안정화 거듭제곱 변환 | 289,371원 | 138,503원 | 0.3451 |
| Adaptive Winsorized | 1% 절단 후 RobustScaler | **289,168원** | **138,466원** | **0.3460** |

### StandardScaler를 최종 채택한 이유
1. **LightGBM에서의 최저 오차 달성**: 256개 히스토그램 빈 양자화 과정에서 수치적 안정성을 제공하여 검증 오차(289,168.1원)가 가장 낮았습니다.
2. **이상치 절단 없이 원래의 데이터 특성 유지**: 인위적으로 상하위 값을 자르는 윈저화나 정규분포로 억지로 왜곡하는 변환과 달리, 원본 데이터의 분산 형태를 자연스럽게 유지합니다.
3. **앙상블 및 타 알고리즘과의 호환성**: 향후 선형 회귀, 신경망, 또는 KNN과 같은 다른 알고리즘과 결합하여 모델을 확장할 때도 표준화(평균 0, 분산 1)는 가장 안정적이고 널리 권장되는 전처리 기법입니다.

## 5. 4단계 핵심 질문 답변 및 소결

> **[핵심 질문] 왜 해당 전처리를 선택했으며 누수를 어떻게 방지했는가?**
>
> 1. **StandardScaler를 선택한 이유**:
>    - 트리 모델은 이론적으로 스케일링에 영향을 덜 받지만, LightGBM의 256개 히스토그램 구간 분할 시 수치 안정성이 소폭 개선되어 가장 낮은 검증 RMSE(289,168원)를 보였습니다.
>    - 아울러 거리 기반 모델(KNN) 등 단위 차이에 민감한 다른 알고리즘과의 결합 시에도 거리가 왜곡되지 않도록 보장하는 가장 범용적인 전처리이기 때문입니다.
> 2. **누수를 방지한 방법**:
>    - 모든 스케일러의 평균과 표준편차는 **오직 훈련 데이터(1,728건)에서만 계산(`fit`)**했습니다.
>    - 검증 세트와 테스트 세트에는 훈련 세트에서 계산된 평균과 분산을 그대로 적용하여 **변환(`transform`)만 수행**함으로써 미래 데이터의 분포가 모델 학습에 유입되는 것을 완벽히 차단했습니다.

다음 장에서는 이렇게 전처리된 데이터와 최적 튜닝 파이프라인을 최종 동결하고, 미사용 독립 테스트 세트에서 모델의 최종 일반화 성능을 검증하겠습니다.
