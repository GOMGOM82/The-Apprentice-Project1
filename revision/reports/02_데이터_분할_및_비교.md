# 2. 데이터 분할 및 비교 분석

## 1. 데이터 분할의 목적과 필요성

머신러닝 모델을 만들 때 학습용 데이터에만 지나치게 맞춰져 새로운 데이터를 제대로 예측하지 못하는 현상을 과적합(Overfitting)이라고 합니다. 이를 방지하고 모델이 실전에서 얼마나 잘 작동할지 객관적으로 검증하기 위해 데이터를 훈련, 검증, 테스트용으로 나누는 작업이 필수적입니다.

본 장에서는 2,880건의 여행 데이터를 바탕으로 과제에서 요구하는 두 가지 분할 방식인 2분할(Train/Test 8:2)과 3분할(Train/Validation/Test 6:2:2)의 특성을 비교하고, 특히 검증 데이터(Validation Set)의 존재 유무가 모델 개발과 성능 평가에 어떤 실질적인 차이를 가져오는지 살펴봅니다.

---

## 2. 테스트 데이터 선정 및 2단계 분할 방식

### 2.1 무작위 비복원 추출 방식
테스트 데이터를 나눌 때 파일의 앞쪽 80%와 뒤쪽 20%를 단순히 잘라내는 순차 분할을 적용하면, 특정 계절이나 특정 지역에 데이터가 편중되는 문제가 생길 수 있습니다.

따라서 Scikit-Learn의 `train_test_split` 함수를 활용해 전체 2,880건의 표본을 무작위 순열로 섞은 뒤(shuffle=True, random_state=42), 비복원 추출 방식으로 정확히 20%에 해당하는 576건을 독립 테스트 세트로 먼저 떼어냈습니다.

### 2.2 2단계 계층 분할 구현
전체 2,880건을 한 번에 나누지 않고 다음과 같이 2단계로 나누었습니다.

```python
# 1단계: 전체 2,880건에서 테스트 세트 20%(576건)를 무작위 추출하여 격리
X_dev, X_test, y_dev, y_test = train_test_split(
    X, y, test_size=0.20, random_state=42, shuffle=True
)

# 2단계: 남은 2,304건(80%) 내부에서 훈련 세트 60%(1,728건)와 검증 세트 20%(576건) 분할
X_train, X_val, y_train, y_val = train_test_split(
    X_dev, y_dev, test_size=0.25, random_state=42, shuffle=True
)
```

이와 같이 나누면 2분할(8:2)에서 쓰이는 테스트 세트(576건)와 3분할(6:2:2)에서 쓰이는 테스트 세트(576건)가 난수 시드(42)를 기준으로 정확히 일치합니다. 이렇게 평가 대상을 고정해 두어야 분할 방식 간의 성능 차이를 공정하게 비교할 수 있습니다. 분리된 테스트 데이터 576건은 `data_splits/test_dataset_seed42.csv` 파일로 따로 저장해 두고 튜닝 중에는 열어보지 않도록 격리했습니다.

## 3. 내부 비교 실험: 검증 데이터 유무에 따른 차이

과제의 지침인 "테스트 데이터는 모든 튜닝이 끝난 뒤 최종 1회만 사용한다"는 원칙을 지키기 위해, 2단계 비교에서는 테스트 세트를 열지 않고 개발 데이터 내부의 검증 세트(576건, 이하 세트 H)를 공통 평가 기준으로 삼아 두 가지 접근 방식을 비교했습니다.

1. 전략 A (검증 데이터가 없는 환경 모사):
   - 훈련 데이터 1,728건으로만 학습하고, 별도의 튜닝 없이 기본 파라미터(RandomForest 및 LightGBM 기본 설정)를 그대로 적용한 뒤 세트 H에서 결과를 확인합니다.
2. 전략 B (검증 데이터를 활용하는 환경):
   - 훈련 데이터 1,728건으로 학습하되, 세트 H의 오차를 모니터링하면서 과적합을 억제하도록 트리의 깊이나 학습률을 조절합니다.

### 실제 성능 비교 결과

개발 세트 내부의 평가 세트 H(576건)에서 측정한 두 전략의 성능 비교는 다음과 같습니다.

| 분할 전략 및 적용 모델 | 훈련 표본 수 | 평가 표본 수 | 평가 세트 RMSE | 평가 세트 MAE | 평가 세트 $R^2$ | 훈련 세트 $R^2$ | 훈련-평가 격차 ($R^2$) |

| 전략 A: RandomForest 기본 모델 | 1,728건 | 576건 (H) | 299,664원 | 148,830원 | 0.2143 | 0.9248 | 0.7105 (심각한 과적합) |

| 전략 B: 검증 튜닝 LightGBM | 1,728건 | 576건 (H) | 289,168원 | 138,466원 | 0.3460 | 0.5570 | 0.2110 (과적합 60% 완화) |

## 4. 결과 해석

비교 결과는 검증 세트가 모델 개발에서 왜 중요한 역할을 하는지 명확하게 보여줍니다.

1. 검증 세트가 없을 때 발생하는 훈련 오차 착시:
   - 전략 A처럼 훈련 데이터의 점수만 모니터링할 경우, RandomForest는 훈련 $R^2$가 0.9248, LightGBM은 0.8175로 나와 모델이 지출 패턴을 아주 잘 맞히고 있는 것처럼 착각하기 쉽습니다.
   - 그러나 이 모델을 학습에 쓰이지 않은 데이터(H)에 적용해 보면 $R^2$가 0.21~0.28로 급락합니다. 훈련 점수와 실전 점수 사이에 0.54~0.71에 달하는 큰 격차가 생기며, 개발자는 과적합이 발생했다는 사실조차 파악하기 어렵습니다.
2. 검증 세트를 통한 과적합 통제:
   - 전략 B처럼 검증 세트를 보면서 트리의 깊이를 제한(`max_depth=3`)하면, 훈련 $R^2$는 0.81에서 0.55로 낮아지지만 실제 평가 데이터에서의 RMSE는 302,706원에서 289,168원으로 13,538원(약 4.5%) 줄어들고 $R^2$는 0.2769에서 0.3460으로 약 25% 향상됩니다.
   - 훈련 세트와 평가 세트의 격차 역시 0.5406에서 0.2110으로 60% 이상 축소되어 안정적인 모델을 만들 수 있었습니다.

> [핵심 질문] 검증 데이터가 있을 때 무엇이 달라지는가?
>

> 
> 검증 데이터가 없으면 훈련 점수($R^2 \approx 0.92$)에 속아 모델이 완벽하다고 생각하기 쉽지만, 검증 데이터를 두면 미학습 데이터에서의 실제 성능($R^2 \approx 0.21$)이 곧바로 드러납니다. 이를 길잡이 삼아 트리의 복잡도를 줄이는 규제를 가할 수 있고, 결과적으로 미평가 데이터에서의 예측 오차를 실질적으로 낮출 수 있습니다.
> 
> 또한 검증 세트가 중간 평가를 전담해 주기 때문에, 맨 마지막에 쓸 독립 테스트 데이터를 튜닝 과정에서 오염시키지 않고 깨끗하게 지킬 수 있습니다.

다만 3분할을 적용하면 훈련에 쓸 수 있는 표본이 2,304건에서 1,728건으로 줄어든다는 점은 데이터가 적을 때 고려해야 할 한계입니다.
