# [제2장] 데이터 분할 및 비교

## 1. 목적 (Objective)
본 단계의 목적은 머신러닝 모델의 학습 및 평가를 위한 데이터 분할 전략을 수립하고, **검증 데이터(Validation Set)의 유무가 모델 개발 및 일반화 성능 평가에 미치는 영향을 실증적으로 비교**하는 것입니다.

특히 과제의 핵심 유의사항인 **"테스트 데이터는 모든 튜닝이 끝난 뒤 최종 1회만 사용한다"**는 원칙을 준수하기 위해, 테스트 세트에 접근하지 않고 개발 데이터 내부에서 공정하게 분할 전략을 검증하는 방법론을 확립합니다.

---

## 2. 사용 자료 및 방법 (Data & Methodology)

### 2.1 분할 구조 및 표본 크기
정제된 2,880건의 표본에 대해 고정 난수 시드(`random_state=42`)를 적용하여 다음과 같이 분할하였습니다:
- **전체 표본**: $N = 2,880$건 (2,880명의 고유 여행자로 구성된 독립 표본)
- **독립 테스트 세트 (Test Set)**: 전체의 20%인 **576건**을 사전에 물리적으로 격리하여 `data_splits/test_dataset_seed42.csv`로 영구 보관하고, 모델 튜닝 및 개발 과정에서 일체 접근을 차단함.
- **개발 데이터셋 (Development Set)**: 나머지 80%인 **2,304건**을 모델 훈련 및 검증을 위한 내부 개발 데이터로 확보함.

### 2.2 테스트 데이터 선정 및 추출 방식 (Sampling Methodology)
테스트 데이터를 어떻게 추출했는가에 대한 구체적인 추출 메커니즘과 학술적 근거는 다음과 같습니다:

1. **무작위 비복원 단순 임의 추출 (Simple Random Sampling without Replacement)**:
   - 특정 날짜나 파일 순서대로 앞 80%와 뒤 20%를 잘라내는 **단순 순차 분할(Sequential Slicing)을 배제**하였습니다. 순차 절단 시 특정 수집 기간(예: 성수기/비수기)이나 특정 지역에 데이터가 편중되는 표본 선택 편향(Selection Bias)이 발생하기 때문입니다.
   - 대신 Scikit-learn의 `train_test_split`을 사용하여 전체 2,880건 표본을 의사 난수 순열(Random Permutation)로 완전히 셔플(Shuffle)한 후, 비복원 방식으로 균등 무작위 추출을 수행했습니다.
2. **2단계 계층 분할 구현 코드 (`random_state=42`)**:
   ```python
   # 1단계: 전체 2,880건에서 테스트 세트 20%(576건)를 무작위 비복원 추출하여 완전 격리
   X_dev, X_test, y_dev, y_test = train_test_split(
       X, y, test_size=0.20, random_state=42, shuffle=True
   )
   # 2단계: 남은 2,304건(80%) 내부에서 훈련 세트 60%(1,728건)와 검증 세트 20%(576건) 분할
   X_train, X_val, y_train, y_val = train_test_split(
       X_dev, y_dev, test_size=0.25, random_state=42, shuffle=True
   )
   ```
3. **2분할과 3분할 테스트 세트의 불변성 (Bit-level Invariance)**:
   - 2분할(8:2)의 테스트 세트(576건)와 3분할(6:2:2)의 테스트 세트(576건)는 동일한 시드(`seed=42`)와 동일한 1차 분할 단계에서 추출되었으므로, **행 순서와 데이터 내용이 비트 단위로 100% 동일**합니다.
4. **연속형 타깃의 분포 보존**:
   - 타깃 변수(`TOTAL_EXPENDITURE`)가 연속형 금액(3,000원 ~ 5,340,850원)이므로 범주형 층화 추출(Stratified Split) 대신, 무작위 셔플을 통해 훈련 세트(평균 34.0만 원)와 테스트 세트(평균 36.0만 원) 간의 통계적 분포와 왜도(Skewness 3.63)가 왜곡 없이 자연스럽게 보존되도록 하였습니다.

### 2.3 내부 비교 설계: 공통 개발용 비교 평가 세트($H$)
최종 테스트 세트의 격리 원칙을 훼손하지 않기 위해, 지시서 제5.4조에 따라 개발 데이터(2,304건) 내부에서 공통 평가 세트 **$H$ (검증 세트 576건)**를 분리하고, 나머지 **1,728건(60%)**을 훈련 세트로 고정하여 두 가지 전략을 비교하였습니다:
1. **전략 A (검증 세트 부재 전략 / 2분할 환경 모사)**:
   - 별도의 검증 세트를 활용한 튜닝 없이, 훈련 데이터(1,728건)에 고정 기본 알고리즘(RandomForest 및 LightGBM Default)을 학습시킨 후 $H$에서 성능을 평가합니다.
2. **전략 B (검증 세트 활용 전략 / 3분할 환경)**:
   - 훈련 데이터(1,728건)로 학습하되, 검증 세트 $H$(576건)의 오차를 지속적으로 모니터링하여 과적합을 방어하는 하이퍼파라미터를 탐색·선택합니다.

## 4. 해석 (Interpretation)

실험 결과는 검증 세트의 존재 여부가 모델의 품질과 신뢰성에 결정적인 차이를 만들어냄을 실증합니다:

1. **검증 데이터 부재 시의 '훈련 오차 착시' (전략 A의 한계)**:
   - 검증 데이터 없이 학습 데이터의 성능만 모니터링할 경우, RandomForest는 훈련 $R^2$가 **0.9248**, LightGBM은 **0.8175**에 달하여 모델이 데이터를 완벽하게 학습한 것처럼 오인하게 됩니다.
   - 그러나 실제 미평가 데이터($H$)에 투입했을 때의 결정계수는 0.21~0.27로 폭락하며, **0.54~0.71에 달하는 극심한 과적합 격차(Generalization Gap)**가 발생합니다. 즉, 모델 개발자는 자신이 만든 모델이 실전에서 무용지물이라는 사실조차 인지할 수 없습니다.
2. **검증 데이터 존재 시의 '객관적 통제 및 최적화' (전략 B의 우수성)**:
   - 독립된 검증 세트 $H$를 피드백 지표로 삼음으로써, 모델의 훈련 $R^2$가 0.81에서 0.55로 인위적으로 억제(규제)되더라도, **실제 검증 세트에서의 RMSE는 302,706원에서 289,168원으로 13,538.1원(4.47%) 감소하고 결정계수($R^2$)는 0.2769에서 0.3460으로 24.9% 향상**되었습니다.
   - 과적합 격차 역시 0.5406에서 0.2110으로 **60.4% 축소**되었습니다.

## 5. 단계별 미션 답변 (Key Mission Answer)

> **[과제 핵심 질문] 검증 데이터가 있을 때 무엇이 달라지는가?**
>
> **검증 데이터(Validation Set)가 존재할 때 달라지는 핵심은 '과적합(Overfitting)의 조기 감지'와 '공정한 모델 선택의 기준 확보'입니다.**
> 
> 1. **과적합 착시의 방지**: 검증 데이터가 없으면 개발자는 훈련 점수($R^2 \approx 0.92$)에 현혹되어 모델이 고도로 정확하다고 착각하게 됩니다. 검증 데이터는 모델이 학습하지 않은 표본에서의 실제 성능($R^2 \approx 0.21$)을 즉각 노출시켜 심각한 일반화 오류를 가시화합니다.
> 2. **객관적인 튜닝 나침반 제공**: 검증 오차를 목적함수로 설정함으로써, 트리의 깊이 제한(`max_depth=3`)과 같은 규제(Regularization)를 과감히 적용할 수 있게 되며, 그 결과 미평가 데이터에서의 예측 오차를 유의미하게 낮출 수 있습니다.
> 3. **테스트 데이터의 순수성 보존**: 검증 데이터가 중간 평가 역할을 전담하므로, 최종 평가용 테스트 세트를 오염시키지 않고 온전히 보존할 수 있습니다.
